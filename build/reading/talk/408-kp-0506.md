# 拓扑排序：它一边排顺序，一边就是那个环的检测器

> 讲解稿｜源：`notebook/kaoyan/note/408/ds/408-DS-0506-拓扑排序.md`｜主题：排序过程本身就在检查有没有环——能排完就是无环，排不完就是有环

## 先回答三个为什么

**为什么有的先后顺序不能自己随便定。**

先把场景摆出来：一堆活，每条"某活必须在某活之前做完"的规矩单独看都不难。难的是把它们摆到一起，排出一个人人服气、从头到尾不违规的次序。

如果只有一条规矩，从它说的那个先做就是了。规矩一多，就会互相牵扯：这件事要等那件事，那件事又要等第三件。你随便挑一个开工，很可能干到一半发现前提没满足，只能回头。

所以要的不是"小心点排"，而是一个能保证任意多条规矩同时成立的排法。它要么给你一个合格次序，要么明确告诉你：这堆规矩本身是矛盾的，不存在合格次序。

**为什么用"谁还没被等过"这一条线索来挑。**

规矩都是"先做某件"的形状，所以每件活都有两个数：它等了别人几件，以及别人等它几件。

一件活如果一件都不用等，它现在随时可以开工。这就是唯一能确定动工的候选。

把它做掉之后，那些等它的活就少了一份等待。等待数掉到零的，立刻加入候选。

没有这条线索会怎样？你得每次从头看一眼全局，判断"当前这堆还没做的里面，谁的规矩全被满足了"，而这件事每次都要重新数一遍所有规矩。把每件活被等了几件记成一个小账本，是唯一让这件事能边做边更新的办法。

**为什么这件事能顺手把环查出来。**

回路的意思是：一圈活互相等着，绕回自己。你顺着规矩看，这一圈里哪一件都不能先开工，因为它们各自都还有人在前面挡着。

那就必然出事：如果图里藏着这么一圈，那么无论你怎么挑，挑到最后总会剩下一堆谁的等待数都不为零的活。你的候选集合会空掉，可活还有剩——这就是没排完。

反过来，只要全程挑得出候选、所有活都被排掉了，就说明一路上从没有卡住的地方，也就没有那一圈互相等待的活。

所以排序过程和查环不是两件事，是同一件事的两个说法。这是这个考点真正的那句话。

## 往后会接到哪

这条线往下是关键路径：拓扑序给了正着推的那一趟，把它的顺序反过来，正好是反着推最晚时间的顺序。

再往后，判断依赖是否成环这件事，在编译器和任务调度里都直接用它，一个模块的引用关系就是一张这样的图。

## 一类问题，四个场合

它只有一类：一串活，加一批"谁必须在谁前面"的规矩。

四个场合：判断一个候选次序合不合法、数一共有几个合法次序、用它查环、看存储结构定代价并说清反向序列。

四种场合里，那条"挑等待数为零的活"的规则一次都不改。真正分叉的地方只有三处：中途的候选是怎么补进来的、收尾时怎么判、以及换一种存储怎么算账。

一句结论：只有这几格需要你说清理由，其余全是同一条规则的复述。

## 哪几格不一样

先说原则：**每摘走一件活，就去减一次等它的那些活的账；账减到零，它才进候选。** 这句话一以贯之，所有岔路都长在"账什么时候重算"上。

**判断候选次序是否合法：** 不必真跑一遍算法。把每条规矩翻译成"某件排在另一件前面"，再按候选次序给每件活标上位置号，逐条比位置大小，有一条反了就否掉。原因：合法次序的全部含义就是每条规矩都顺着排。

**这里最容易漏的一格：** 必须逐条核对跨位的那条规矩，不能只看相邻两件。原因：两件不相邻的活之间完全可能有规矩，跳过去就漏判。开头那一件碰巧在等候数为零之列，也不代表整个次序成立。

**数合法次序有几个：** 用枚举的方式，每步把当时所有候选取出来，挨个试一遍，摘掉一个就重算它那些后继的账，再往下走，最后把各分支的个数加起来。原因：候选只有一个时不必分支，直接往下。

**这一格的错误做法：** 把候选的个数当成能任意互换的排列，直接算排列数。原因：摘掉一个候选后新候选会补进来，能换谁不能换是动态的，静态算排列会多算也会少算。

**查环：** 只看最后输出的活够不够。够了就是无环，少一件就是有环。原因：一圈互相等待的活，账永远减不到零，安静地留在最后。

**这一格最容易错的地方：** 看到图上还有等候数为零的活，就断定没有环。原因：环外面完全可以挂着别的不相关的活，它们照样排队，环还藏在里面。

**代价：** 按点表存时是 O n 加 e，按矩阵存时退成 O n 平方。原因：每件活、每条规矩各处理一次；换成矩阵，找后继得扫一整行。先把存法看清楚再写量级。

**反向序列：** 把正着排出来的序列整个倒过来。原因：每条规矩方向反转，原来"先完成才能开始"就变成"先收尾再往前推"，所以它正好是倒着推的时间顺序。

**序列独不独一份：** 一般不止一种，但不等于一定不止一种。原因：所有活恰好穿在一条链上时，每一步候选就只有一个，次序被唯一确定。

## 三个坑，一句话边界

坑一，把"有活可以开工"当成"没有环"的证据。这两件事没有推论关系，环可以藏在旁边。

坑二，不管存法一律报 O n 加 e。换了矩阵就得扫整行，这个量级不跟着存储走就一定错。

坑三，只查相邻两件就判次序合法。规矩可以跨越很远，逐条比位置号才是完整做法。

边界：这套排法只对有向图才谈得上。有向无环一定排得出，排得出也一定有向无环，两个方向都成立。图里一旦有环，它能告诉你有环，但不会替你指出环在哪儿。
