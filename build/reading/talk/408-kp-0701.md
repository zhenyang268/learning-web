# 排序的好坏不是一维的：快，只是五种代价里的一种

> 讲解稿｜源：`notebook/kaoyan/note/408/ds/408-DS-0701-基本概念.md`｜主题：八种算法不是八个答案，而是五种代价各自取舍后的五个格子

## 先回答三个为什么

**为什么「快」这一条不够用。**

你手上有一批记录，每个记录是一串字段加一个关键字，排序就是按关键字把它们排成不降的次序。只问速度，这件事很清楚：比较次数少、移动次数少，就赢。快排平均 O n log n，比冒泡的 O n 平方 快得多，结论似乎没有悬念。

可真实的记录不只是关键字。一条记录后面可能挂着别的字段，比如一个学生有姓名、有成绩，成绩相同的时候原本谁在前谁在后，是有意义的。如果排序过程把两个成绩相同的人的顺序颠倒了，速度再快，这批数据也已经被你用坏了。

**为什么代价必须是五种，而不是一种。**

你自己写选择逻辑的时候，会不自觉地按比较次数选算法。但排序的代价有五个方向，每一个方向都可能单独成为某一题的答案。

时间是总的比较与移动量，空间是除了待排记录之外还要额外借多少地方，稳定性是相同关键字原本的先后会不会被改掉，原地是说除了常数个暂存位置之外不再开内存，比较次数则是另一条线——有些算法对数据只做分配、根本不比较，比较次数这一栏直接不成立。

上一门课里你用二分找位置会觉得「比较少了就快了」，排序这里不能这么推。比较少不等于移动少，也不等于省空间，更不意味着稳定。这五条是并排的，没有哪一条能推出另一条。

**为什么第一刀要切在「装不装得下」。**

内部排序与外部排序的分界线不在记录条数，而在待排记录能不能一次全部装进内存。

装得下，所有记录都摆在内存里，比来比去没有任何额外负担，你关心的就是上面那五种代价怎么取。装不下，记录散在外存上，每读一遍、写一遍都是慢动作，代价表整个换了主角：读写外存的次数本身就是答案，优化方向变成加大归并路数、减少初始归并段数。

如果这一刀切错，你会把一个大数组当成外部排序去做，然后去算它的归并趟数，方向从一开始就偏了。判据是内存容量，不是数字有多大。

## 往后会接到哪

这五条代价最后会收成一张总表，所有的算法都塞在同一张表里比。再往后，判一堆记录之外能不能一次装完这件事，会展开成多路归并与最佳归并树那一套东西。

## 五种代价，八个算法

这块没有分类，是概念层压在五个指标上：稳定性、时间、空间、原地、比较次数。

同一条现象要在五个格子里分别给答案。比如直接插入在数据基本有序时几乎不用移动，这一句话只动了时间那一格，稳定性那一格它一格没动。

一句结论：五格里有四格大多数算法答案相同或接近，真正决定题目对错的只有那几格不一样的。

## 哪几格不一样

先说原则：**五个指标互相独立，任一条都不能从另一条推出来。** 快和稳不是一回事，慢和不稳也不是一回事。

**稳定性。** 只看一条：相同关键字的相对次序会不会被改掉。判据是「有没有一次距离较远的搬移」——一趟只跟相邻元素打交道、相等时不交换的，稳定；出现跨多元素的交换或把末尾换到开头的，先怀疑。判一次只要找到一个反例，不必查所有输入。

**稳定性与输入是否有序。** 这一格最容易错。稳定性只取决于比较时用的是大于还是大于等于、相等元素要不要继续往后挪。数据基本有序只影响移动次数，对稳定性一个字都不说明。

**时间。** 分平均和最坏两个数。快排的平方级最坏只在特定输入配特定枢轴策略时才发生，别把它读成「快排一定比插入慢」。某算法最坏是平方级，也不能因此判它不稳定，两条线各走各的。

**空间与原地。** 常被一并当成内部排序的免费属性，其实不是。快排的递归栈不是常数，归并的辅助数组也不是常数。只有明确不开额外内存的，才算原地。

**比较次数。** 这一格和速度是两件事。有一种做法把每趟「找插入位置」的比较从线性压到对数级，但找到位置之后整段后移一个没少，总时间还是平方级。比较次数降了，时间没降。

**内部与外部。** 由内存容量定，不由记录条数定。装得下就是内部排序，五个代价都算；装不下就是外部排序，焦点换成读写外存的次数。

## 三个坑，一句话边界

坑一，把「平均 O n log n」和「稳定」捆在一起。这条对数级的算法里，稳的和不稳的都有，绑着记必然整题误判。

坑二，看见某个算法在基本有序时几乎不动，就判它稳定。它动得少，和它遇到相同关键字时谁先谁后，是两回事。

坑三，看某趟之后的序列，发现前几个元素有序就认成插入类。选择排序跑若干趟之后，前几个是全局最小的那几个且有序；插入类的前几个只是原序列前几个自己内部有序。两者元素集合不同，只数有序长度、不看集合内容就会认错。

边界：这五格只在内部排序里摆得齐。记录装不进内存之后，稳定性和比较次数基本退出讨论，主角换成归并趟数。
