# 堆的意义只有一个：把「谁是最大的」从走一遍变成了走一条路

> 讲解稿｜源：`notebook/kaoyan/note/408/ds/408-DS-0704-选择排序与堆.md`｜主题：堆把找最值的线性扫描换成了沿一条路径下沉，代价是必须先花一次建堆

## 先回答三个为什么

**为什么会有「选择」这条路。**

插入和交换都在做同一件事：一边比一边动，动完再比。选择把它们彻底拆开——先在整个无序区里找出最小的那个，然后一次换到前面。

这个拆法有一项便宜：比较的次数固定下来了。不管数据本来多有序，也不管多乱，要找最小值就得把无序区走一遍，一趟就是那么多次比较，一次省不掉。所以选择排序的比较次数与初始序列完全无关。

**为什么简单选择快不起来。**

它每一趟都要在无序区里扫一圈，找最小值那一步是线性的，而一趟只定死一个元素，账一乘就是平方级。

真正麻烦的是每一趟都在重复同一件苦力：这一趟扫完知道了谁最小，下一趟把这条信息全丢了，从头再扫。如果有个结构能把「谁最大」随时挂在手边，就不必每趟重扫了。这就是堆要解决的问题。

**为什么是「堆」这种形状。**

堆做的事很朴素：它要求每一个结点都不小于它的两个孩子。只要求父子这一层关系，不要求左右谁大也不要求整棵树有序。

这条要求看着稀松，但它有一项性质正合用：根永远是全树最大的那个。所以你随时问「谁最大」，答案就在根上，一步取到。

代价是要维持这条性质。改了一个位置，可能就破了父子关系，得顺着被破坏的那一侧往下修——但这只需沿着一条路径走，因为只有那一个分支被破坏了。一次修复是 O log n，而不是线下扫描的 O n。

**为什么建堆有两种做法，而且不一样。**

手上有一堆乱序记录，怎么把它弄成堆。

一种做法是逐个插进来，每插一个就往上冒到合适的位置，共插那么多次，每次至多走一条到根的路径，总共是 O n log n。

另一种做法是就地调整：先把它当成一棵完全二叉树，从最后一个非叶结点开始，往前逐个往下沉。绝大多数结点都在最底层，它们几乎不用沉；越靠上的结点越少，但沉得越远。把每个结点的高度加起来一算，总和是 O n。

两种做法不只复杂度不同，最后得到的那棵树也可能长得不一样。这是这一段最容易崩的地方。

## 往后会接到哪

「顺着一条路径修一处破坏」这个动作，平衡树的旋转里会再见到一次。再往后，堆还会以「优先级队列」的身份出现在别的地方。

## 两类，一个动作

分类两个：简单选择、堆排序。简单选择每一趟现扫一遍找最小值，堆排序把这份答案提前维持成结构。

功能摊开是：找当前最值、把它放到该在的位置、维持结构、建初始结构、稳定与否。

一句结论：**五格里大多数动作两类都在做，真正分家的只有「找最值」这一格——一个是扫描，一个是沿路下沉。**

## 哪几格不一样

先说原则：**两类的差别不在排法，而在「最值怎么来」。简单选择是每次现找，堆排序是提前养着一个随时能问的结构。**

**简单选择 · 找最值。** 在无序区里完整扫一遍，比出最小。比较次数恒为 n 乘 n 减一 再除以 2，和初始序列无关。为什么：不管数据什么形状，找最小值都得看每个元素一眼。

**简单选择 · 放到位。** 用它和无序区的第一个元素对调。移动次数可以为零——刚好已经在位时就一次都不动。为什么：一趟只交换一次，这是它比较省的地方。

**简单选择 · 稳定吗。** 不稳。它做的正是距离较远的那一次对调，一个元素可能被一步跨过好几个相同关键字。看到「每趟只交换一次」就判它稳定，是这一格最典型的误判。

**简单选择 · 和冒泡的区别。** 冒泡是相邻对调，把最值送到无序区末端；选择是远端对调，把最小值送到前端。同样一趟定死一个，走的距离完全不同。

**堆排序 · 找最值。** 直接取根，一步到位。为什么：父子的大小关系保证了根是全树最大。这一格就是整件事的全部收益。

**堆排序 · 建初始堆。** 从最后一个非叶结点出发，自底向上、由右向左逐个下沉，每做完一棵子树它就是合法堆。总代价 O n。为什么：多数结点在最底层，下沉距离接近零。

**堆排序 · 下沉怎么做。** 拿待修结点和两个孩子里较大的那个比，比它小才换，换完沿着被破坏的那一支继续往下查，直到停下。只跟一个孩子比、或者换一次就收手，这一格必错。为什么：交换之后，下面那棵子树的关系也跟着变了。

**堆排序 · 删一个元素。** 把末尾元素搬到根上，然后向下调整一次。为什么：直接删根会让树断开，用末尾补位代价最小，形状还保持完全二叉树。

**堆排序 · 稳定性与空间。** 不稳，也只需常数级额外空间。它在根和末尾之间来回搬，相同关键字会被跨过去。这两条常和别的算法的空间开销一起被问。

## 三个坑，一句话边界

坑一，把建堆当成「插入那么多次、每次走一条路径」，于是答成对数级。自底向上逐个下沉是线性级的，两种做法连结果堆都未必一样。

坑二，下沉时只跟一个孩子比，或者换一次就停手。大根堆要和较大的那个孩子换，换完还得顺着被破坏的那一支继续看。

坑三，觉得「父大于子」就意味着整棵树有序，把它当成二叉排序树来推。堆只保证父子这一层的大小关系，左孩子与右孩子的顺序完全不定，次大值只在根和根的两个孩子三个位置之中。

边界：堆的优势全在「反复问最值」这类场合。如果只要排一次序、记录又少，为了那一步取根去维持一棵树反而亏；它不稳，要求保住相同关键字原序时就不能用它。
