# CPU 快得没边、外设千奇百怪，中间必须有人替它们两头对口径

> 讲解稿｜源：`notebook/kaoyan/note/408/co/408-CO-0703-IO-接口.md`｜主题：接口站在主机与外设之间，做速度与格式的双重翻译

## 为什么中间要插一块东西

**为什么处理器不能直接插到外设上。**

主机这边是并行总线，一次送出若干位，电平是标准的，时序卡在节拍上。外设那边不是这样：磁盘传的是成串的位，键盘一次给几个编码，打印机吃的是并行的字模信号。格式不一样，直接对接就是各说各话。

速度更麻烦。处理器一个周期几纳秒，机械磁盘找一道要几毫秒，两边差六个数量级。没有中间缓冲的那一拍，CPU 就得空等机械动作完成，算得再快也是白算。

接口就是站在这条缝里的那块硬件：一端挂系统总线，一端接外设本体，两头各说各的方言，它负责翻译。

**为什么翻译不能只靠软件。**

全靠 CPU 逐位拼串行数据，每搬一位都要执行几条指令，一个字节就吃掉几十个周期。管脚还接不上，CPU 的引脚是总线信号，和外设的时序对不上。

所以翻译必须是硬件干的，而且必须贴着外设那一侧：把串并转换、电平匹配、缓冲这些活从这里接走，CPU 那边就只剩「读一个字、写一个字」两个动作。

**为什么这块硬件非要带一组寄存器。**

没有寄存器会怎样？地址译码就白做了。你选中了这个设备，可上一次送来的数据无处暂存，也拿不到它「准备好了没有」的答复，CPU 只能靠猜，或者干脆按固定延时死等。

三个寄存器把这件事切成三段：数据寄存器暂存这一次的值，状态寄存器回答「能不能传」，控制寄存器接收「接下来做什么」。有了这三格，任何外设都能被同一套读写的动作访问，不管背后是磁盘还是键盘。

## 往后会接到哪

这套「地址选设备、寄存器分角色」的模型，往后就是那三种 I/O 方式的公共底座：查询靠反复读状态，中断靠状态触发一根请求线，DMA 靠控制器替 CPU 发地址。再往后到虚拟存储，主存也变成了外设那一侧，接口换名字叫存储管理部件，问题还是速度匹配和格式换算。

## 四类部件，四件功能

功能归四类：寻址、速度匹配、格式转换、状态与联络。

内部部件也归四类：地址译码器、数据缓冲寄存器、串并转换与格式逻辑、状态寄存器加中断逻辑。

一句结论：这四类部件各自对着四件功能，格子看似十六格，其实只有「谁产生信息、谁读谁写」和「是不是真挂在主机与外设之间」这两处会考到。

## 哪几格不一样

**原则：接口的身份由位置决定，不由名字决定。** 一端挂在 CPU 或系统总线的内部逻辑上、另一端并不直接对着外设的部件，不管名字里有没有 I/O 或接口字样，都不是 I/O 接口。

**身份这一格：必须一端总线、一端外设。**

接口是「主机与外部设备之间」的硬件界面，物理上要被夹在中间。主机侧的功能单元，比如总线控制器、中断控制器，虽然也在总线和 CPU 之间，但它们调度的是主机内部事务，另一头没有外设。

磁盘驱动器这一类本身就是外设，是被接口牵着的那一方，位置反了。

**数据寄存器这一格：双向，读和写都可能。**

它暂存的是这一次传送的那份数据，输入时外设写进来、CPU 读走，输出时 CPU 写进去、外设取走。说它「只读」或「只写」都不成立。

**状态寄存器这一格：外设一侧写、CPU 一侧读。**

信息由谁产生，方向就归谁。设备忙不忙、出错没有、缓冲空不空，这些是接口从外设那边收集来的，CPU 只负责读。

把它说成「CPU 可读可写」，就等于允许 CPU 替设备宣布自己准备好了，联络立刻失效。

**控制寄存器这一格：CPU 写、接口收。**

启动、停止、定方向，这些是 CPU 下的命令，接口只接收。它和状态寄存器方向正好相反，合成一个「命令与状态寄存器」来记，遇到问方向就会判反。

**速度匹配这一格：目的是补差异，不是扩大容量。**

工作速度差几个数量级，缓冲寄存器用自己那一小片存储，把「快的一方等慢的一方」改成「快的一方一次交一批、接着干别的」。

把它理解成扩容，就会误以为缓冲是为了装下更多数据，答题时方向整段偏。

**中断请求这一格：由接口侧产生，不是 CPU 侧。**

状态寄存器发现「数据备好了」或者「缓冲快空了」，由接口的中断逻辑拉一根请求线上去。CPU 只负责收。

归到 CPU 侧，等于说 CPU 自己给自己发请求，中断存在的意义就没了。

**四类功能这一格：各归各的部件，别串门。**

寻址归地址译码器，速度匹配归缓冲寄存器，格式转换归串并和格式逻辑，状态联络归状态寄存器加中断逻辑。把速度匹配归给译码器，或把格式转换说成软件做，都是把这四类混成了一团。

## 一句话边界

边界：接口管的是「怎么把一次数据送清楚」，不决定这次 I/O 用哪种方式等设备；真正区分谁盯着搬运的，是下一层那三种方式。
