# 三种 I/O 方式吵了几十年，吵的其实是「谁的眼睛盯着那批数据」

> 讲解稿｜源：`notebook/kaoyan/note/408/co/408-CO-0704-IO-方式.md`｜主题：三种方式的差别只在谁盯着数据搬运，CPU 被占多久是结果不是原因

## 为什么会有三种做法

**为什么一开始只能死等。**

早先没有让设备反过来通知 CPU 的通道，CPU 除了自己去看，没有第二条路。

它把启动命令写进接口，然后反复读状态寄存器问「好了没有」，没好在原地再问一遍。设备慢多久，它就等多久，这段时间什么正事也干不了。

不给它一条通知通道会怎样？那就只能等，等是唯一选项。

**为什么加了中断还不够。**

中断把等待去掉了：CPU 启动设备后转身去执行别的程序，设备备好数据，接口拉一根请求线，CPU 在一条指令执行完时响应，转进服务程序把这一个数据搬走。

可它一次只搬一个。搬完返回，设备再去准备下一个，准备好了再中断一次。数据量一大，中断次数跟着涨，每次中断都要关中断、保存断点、保护现场、恢复现场，这一整套固定开销乘上成千上万次，CPU 的时间又赔进去了。

**为什么还要一个控制器替它搬。**

块设备的传送成批、地址连续，这种活有规律，硬件完全能做：给它主存起始地址、字数和方向，它自己加地址、减计数，设备来一个字就往主存里放一个字。

不交给它，CPU 得为每个字再进一次内核，数据量越大越亏。交给它，CPU 只在开头设参数、结尾收个信。

代价是要占总线：它得先申请、拿到总线控制权，才能以主设备身份向主存发读写命令，这期间 CPU 被挡住几个主存周期，或被整块让出。

## 往后会接到哪

这套「谁盯搬运」的分法，往后到操作系统那一章会换词：驱动负责预处理与后处理，中断处理程序负责收尾。判定标准还是同一条：数据搬运的时候，CPU 在不在场。

## 三种方式，四组对照

三种方式：程序查询靠 CPU 反复读状态；程序中断靠设备反向发请求、服务程序搬数据；DMA 靠一个专用控制器接管总线搬一整块。

四组对照：传送粒度、谁在搬数据、CPU 被占多久、适合接什么设备。

一句结论：三个方式的差别全落在「谁盯着这批数据」这一格上，其余几格都是从它推出来的。

## 哪几格不一样

**原则：数据搬运不在 CPU 手里，才算真的脱身。** 只要还是 CPU 执行指令把数据搬进搬出，它就没被解放，中断只是把「等」换成了「被打断」。

**程序查询：CPU 全程在场，串行到底。**

它一个人干两件事，启动设备之后马上原地读状态，读到就绪才搬。设备准备期间 CPU 完全被占住，两者没有一秒钟并行。

好处是接口最简单，只要一根状态线和一组数据线，不必有请求线。所以它只适合慢速、偶发、且 CPU 等得起的外设。

**程序中断：CPU 与设备并行，但每传一个数据被打断一次。**

设备准备数据的那段时间，CPU 在跑别的进程，这一段是真并行。数据一到，接口请求，CPU 在当前指令执行完时响应。

粒度仍是一个数据，固定开销按次数计，总量越大越贵，只适合低速、偶发、需要及时处理的外设。

还有一个门槛：设备准备一个数据的时间要远大于中断处理时间，否则忙不迭地响应中断，比查询还亏。

**DMA：以块为单位，块内 CPU 不在场。**

传送的是整块，搬运由控制器用硬件完成，CPU 在块传送期间基本不介入。固定开销从每字一次降成每块一次，块越大优势越明显。

但它不是全程不管：传送开始前要由设备驱动程序设置主存地址、字计数和方向，结束后控制器发一次中断，由服务程序校验、置状态、唤醒等待的进程。这三段里只有中间那段不经过 CPU。

**数据通路：设备与主存之间，不经过 CPU 也不经过它的寄存器。**

控制器的角色是指挥官，不是中转站。它发出主存地址和读写命令，数据从设备接口直接进主存。

把它画成「设备到控制器再到 CPU 再到主存」，就是把指挥官当成了仓库，这也是最容易丢分的一格。

**总线占用：先申请，拿到再用，方式是窃取或成组。**

控制器必须先成为总线主设备。周期挪用在每个字传送的时刻借走一个主存周期，借完就还，CPU 缓一拍接着访存；成组传送则把整块时间占住，中途不让。

周期挪用不等于整块霸占，块传送期间 CPU 一般只是偶尔被推迟，不是长期不能访存。

**优先级：DMA 请求排在中断请求前面，判据是「谁等不起」。**

中断请求对应「数据备好了，你什么时候来都行」，晚一点不丢。DMA 请求对应「缓冲快溢出了，再不来这个字就没了」，丢了无法补救。

所以优先的是不能被延迟的那一方，不是速度更快的那一方。

**CPU 时间占比：得把单次开销乘上传送次数再比。**

中断是「每次一个数据一份固定开销」，DMA 是「每次一块一份固定开销」。只比单次开销不比次数，会得出和总量完全相反的结论。

算的时候还要看清缓冲宽度和传输率的口径：缓冲是位还是字节，传输率是字节每秒还是位每秒，差一个换算就整题崩。

## 三个坑，一句话边界

坑一，把「CPU 与外设并行」当成错的说法。中断方式下准备数据那一段确实是并行的，判错就放过了真正错误的表述。

坑二，以为数据要先进 DMA 控制器。控制器只发地址和命令，数据走设备到主存这条路。

坑三，把 DMA 的后处理中断当成每字一次中断。那样一算，DMA 的优势就被自己抹掉了。

边界：三种方式只在同样的传送总量下才可比；通道不是第四种独立机制，它只是把「替 CPU 搬」换成「替 CPU 执行一串搬运命令」。
