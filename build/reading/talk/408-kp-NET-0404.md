# 分片是被链路的最大传输单元逼出来的，重组只能等到终点再做

> 讲解稿｜源：`notebook/kaoyan/note/408/net/408-NET-0404-分片与配套协议.md`｜主题：所有字段改动都由两条约束决定——片偏移以八字节为单位记账，重组只在目的主机发生

## 为什么会有分片这回事

网络层想做的事是端到端一次送到，但它脚下每一段链路的脾气不一样：有的一段能扛一千五百字节，有的一段只扛五百多。IP 数据报在源主机发出时按自己的规矩拼，走到某段链路才发现过不去。

**没有分片会怎样。** 要么这条路彻底不用，把整条路径的最大可传长度压到最窄那段链路的水平，宽链路的能力全浪费；要么让每段链路自己重新封装整条报文，跨网互联这件事就不成立了。分片把"过不去"变成"切开了过"：按这段链路的容量切，切完各自走，到终点再拼回来。

**为什么把重组推到最后。** 如果在中间每个路由器都拼一次，下一个路由器可能又要再切一次，同一份数据被反复切拼，路由器还得为未收全的报文留缓存和计时器。把重组放到目的主机，中间路由器就只剩一件简单事:超了就切,转手就走。代价是中途丢任何一片，整份报文都白传,而且目的主机得为收不全的报文挂着缓存等。

**为什么片偏移要以八字节为单位。** 首部空间是有限的，八百字节的数据段用十六位表示偏移绰绰有余，用八字节做单位还能多表示八倍的范围。代价是一个强制约束：每一片的数据长度必须是八的倍数，不然下一片的偏移就不是整数了。除不尽的时候只能向下取最近的八的倍数，剩下的留给末片。

**为什么一个数据报在源端还要传一堆配套协议。** IP 只负责把包送去，它不知道目的主机在哪个网卡上，不知道对方的地址该配什么，也不知道路上哪里断了。这三件事分别交给地址解析、动态配置和差错报告，都是网络层自己的帮手，不是上层的事。

## 往后会接到哪

同一套"上一层把下一层的局限当成前提"的思路，在传输层会被推得更远：IP 说它可能丢、可能乱序，于是传输层自己把确认和重传补上。ICMP 报错用的那个"别再往回发"的原则，也会在传输层的差错处理里再出现一次。

## 五个功能，一块拼图

功能分五块：分片时算切几片、每片多长、偏移填几；判三个标志位各自的语义；地址解析该解析谁的硬件地址；动态地址配置那四步报文的方向；差错报告与两个探测工具的分工。

五块合起来，只有一个总问题：**这个包在过某段链路时被逼着改了什么，改的依据是谁的容量。**

## 哪几格不一样

**算每片能装多少数据：** 先用链路最大传输单元减掉二十字节首部，再向下取到八的倍数。为什么：片偏移以八字节计数，装的数据不是八的倍数，第二片的偏移就落不到整数上。这一步不先做，后面全错。

**算切几片、每片多长：** 从原始数据部分里按上一格算出的容量逐片扣，除末片外都装满，末片放余数，每片都要重新加二十字节首部。为什么：首部是每一片都各带一份的，拿总长直接除以最大传输单元会把首部重复算进去，片数就少了一片。

**偏移填几：** 本片第一个字节在原数据部分里的序号除以八。为什么：偏移记的是"位置"，单位是八字节，不除以八就变成了字节序号，数值大八倍。

**标志位语义：** 一个管"能不能分"，一个管"后面还有没有"，末片那个必须清零。为什么：末片后面确实没有东西了，顺手写成"后面还有"，接收方就会一直等一片永远不来的数据。

**能不能过这段链路：** 只盯一种组合——不许分片而且长度超了。为什么：不许分片又被挡住时，路由器不能切，只能丢掉并回一个差错报文；反之允许分片，超了切开就过去了。

**该解析谁的硬件地址：** 先拿本机掩码与目的地址做与运算，同网段就解析目的主机，不同网段就解析默认网关。为什么：帧只能在同一段链路上传，跨网段时下一跳是网关，帧必须交给它；按"地址长得像不像"判断就会解析错对象。请求是广播、响应是单播，缓存里存的是地址到硬件地址的对。

**地址配置四步：** 客户端先广播找服务器，服务器回一个提供，客户端再广播正式请求，服务器最后确认。为什么：此刻客户端连自己的地址都还没有，源地址只能填零，单播发不出去，所以前三步只能广播，最后一步才可能改成单播。这四个报文带的不只是地址，还有掩码、默认网关和域名服务器。

**差错报文何时不该发：** 对差错报文本身、对非首片的分片、对组播和广播地址、对还不唯一的源地址，都不再发。为什么：不发是为了防止两个设备互相回差错报文停不下来；非首片里没有上层首部，接收方也无从定位是哪个进程出的错。

**两个探测工具的分工：** 一个用回送请求与应答看通不通，另一个靠逐次加大生存时间，让沿途每一跳把包丢掉并回一个超时报文。为什么：回超时的是路上每一台路由器，不是目的主机；把发出者说成目的主机，路径就画不出来了。

## 三个坑，一句话边界

坑一，看到"禁止分片"标志是零就当成不能分；错在把这一位的语义读反了，它是"允许分"。坑二，只改总长度不改标志和偏移；错在把分片当成单纯的截断。坑三，看见某片"后面没有更多"就以为整个数据报只有一片；错在把"我是最后一片"读成"只有我一片"。

边界：分片只在数据报经过的链路容量小于它自身长度时发生，而且每过一段窄链路都可能二次分片，只在源端算一次是不够的。另外，差错报文虽然由网络层产生，它本身是被装进 IP 数据报里传的，属于网络层协议，别往传输层放。
