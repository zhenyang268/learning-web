# content-map.md —— 整站内容总图（规则与理由）

> **读者**：人 + 编码 agent ｜ **定于 2026-11-14**
> **本文件只讲「为什么这样分」**。站点、组、线、章、数值库映射、修正项这些**事实**全部在
> `src/content/content-map.json`，由 `node tools/check-content-map.mjs` 校验。
> **禁止在本文件复述章清单与各类计数** —— 两处各写一份就是漂移的起点。

---

## 0. 一句话

内容总图回答三个问题：**有几站、每一站长什么样、每一块内容归谁**。
它先于任何导入脚本存在：先定结构，再往里灌数据；结构一变就改这张表，不靠记忆。

## 1. 站点为什么分六个

| 站点 | 判据 |
|---|---|
| 数学系 | 自学线，判据是「能证明 / 能看懂」：分析 / 代数与几何 / 概率 / 物理 / 手算 / 索引 |
| 工程数学 | 自学线，判据是「能算 / 能对拍」：数值库 + 数值方法 + 图形学 + 微分方程 + 泛函与弱解 |
| 408 考研 | 应试线，主键是**考纲 KP**，组织维度是「章 → 考点」 |
| 数一考研 | 应试线，另一门科目；与 408 共用外壳，但**考纲主键体系不同** |
| 工程线 | 面试线，组织维度是「能力线 → 项目 → 总览 + NOTES 逐节」，与考试线**单向引用、不互抄正文** |
| 英语一 | 应试线，主键是**题型**（`GE`/`RC`/`WR`/`TR`/`NT`/`CZ`/`VO`），首屏落点是导览 |

**为什么不把 408 与数一合成一个「考研站」**：两套考纲的主键前缀不同（`408-*` 与 `M1-*`），
合站会让「代号 → 路由 → 侧栏」的第一级同时承担两个坐标系；而拆站后每个站只有一套前缀，
`subjects.ts` 的「学科差异只允许出现在一处」也不用破例。

**为什么工程线单独成站**：它的单元是 `OUTLINE` 总览 + `NOTES` 逐节，长度量级与词条完全不同；
混进任何一站都会让「单元 = 一小节」这个前提失效。工程线内部再按**能力线**分组
（代码设计 / 机器与体系结构 / 操作系统 / 数据与一致性 / 性能与并行 / 图形与 AI / 索引），
不按仓库的项目目录平铺；`content-map.json` 的 `lines` 是这张分组表的唯一真源，
`check-content-map.mjs` 只检查**真的登记了线**的站点。

**为什么数学拆成两站（2026-11-17）**：原来的 424 单元一站装完，快照 4.61 MB 顶到预算线，
且两类内容的学习目标不同 —— 测度论/复分析/代数拓扑这类**知道结论并能看懂证明**就够，
数值库/图形学/微分方程要的是**能算、能对拍、能换约束**。混在一站里，
「这条线值不值得展开」没有统一判据。拆分的边界只看一条：**判据是「能算」的进工程数学**。

三处按内容判据跨线搬的章（不是按线搬的）：`AN02` 泛函 / `AN03` 微分形式 /
`AN04` Sobolev·弱解 —— 它们是数值方法与 FEM 的地基；`PR09` 估计量与方差缩减 —— 随机模拟与 CG 的误差口径。
反向留住的：`AG14–16` 李群留在数学系（工程用法已由 `NL09` / `NL13` 镜像覆盖，搬过去就是同一机制两站各讲一遍）；
`PH01–04` 分析力学（含哈密顿）按学科本体留在数学系。

**代号不重排**：搬到工程数学的章仍叫 `AN02`/`NM01`/`CG17`，掌握度与笔记引用不断；
代价是工程数学站必须自带域表（`subjects.ts` 的 `domainTable`），把 `AN` 重新解释成「泛函与弱解」。

六站之间只做**顶栏互链**，数据根完全独立（沿用既有的「两站互不加载对方数据」红线）。
拆分后两站的 `graph/*.yaml` 也各自独立：**跨站的依赖边一律不写**（写进 yaml 就会在另一站报「目标不在索引里」），
只在被删处留一行注释说明该前提在哪个站。

## 2. 数学侧为什么把「域」换成「线」

### 2.1 问题

原层级是 `组 → 域 → 章 → 单元`。**域这一级过重**：有的域下几十个章，展开后一屏全是章号，
读者拿不到中间语义，也没法回答「这一段连起来在讲什么」。

### 2.2 做法

在**组与章之间插一层「线」**，域降级为两件东西：**代号的 2 字母前缀** + **线的归属**。

```
组（6） → 线（若干） → 章 → 单元
```

- 深度仍是四层，**没有变深**；变的只是第二级从「域」换成「线」。
- **线不进代号**：`AN03.2` 仍然是「分析域第 3 章第 2 单元」。所以既有单元、掌握度键、
  `links`、`graph/*.yaml` 全部**零迁移** —— 这是选「加一层」而不是「拆域」的唯一理由：
  拆域要重排全部章号，等于把已收敛的 318 个单元和用户进度一起推倒。
- 一条线只属于一个域，因此在侧栏里**域标签可以挂在线上**（例如「测度与积分 · AN」），
  不必再单独占一级。

### 2.3 硬约束

- **每个章恰好属于一条线**：缺失、重复、未知章都阻断（`check-content-map` 判据）。
- 线内章序 = 学习顺序；跨线的先后由组序与线序决定。
- 线的粒度判据：**读者能一句话说出这条线在讲什么**。说不出来就是切错了 ——
  要么并进相邻线，要么这条线其实是两个主题。

## 3. 数值库：为什么以「库模块」为主键

### 3.1 它不是「再搬两本书」

`notebook/math/` 下已有 `survey/`（横向：库里有什么数学，按库的十一个分支编号）与
`bridges/`（纵向：这些数学是同一个结构动作的不同实例）。**直接把这两册各建成一个单元是错的**——
读者要问的是「矩阵这块数学在库里长什么样」，不是「survey 第几章讲了什么」。

所以数值库域的**章 = 库的模块族**（契约与容差、值与代数、稠密分解、复数、变换与级数、
概率与特殊函数、微分与自动微分、时间积分、几何与李群、离散化、稀疏与迭代、张量、微分形式），
每一章把一个模块的**数学背景 + 设计取舍 + 数值判据**放在一起。

### 3.2 两个来源各管一半

| 来源 | 贡献 | 落在哪 |
|---|---|---|
| `survey/` 的 `know` 条目 | 数学对象、成立条件、**数字判据**、常见误解 | 章内的单元（一个条目一个单元） |
| `bridges/` 的 S1–S6 | 为什么这样设计：换基 / 线性化 / 谱 / 流 / 投影 / 离散 | 工程切入线几章，以及各章的「设计」段 |

条目格式冻结（六字段）：`是什么` / `为什么需要` / `关键结论`（带成立条件）/ `判据`（数字、容差、
异常类型，或「原文未给」）/ `前置` / `常见误解`。缺字段不算风格问题，算没写完。

### 3.3 与主仓 `docs/` 的区别（以 `tol` 为例）

主仓文档只给**规范**：`DefaultTol(n) = 8n·eps`，判主元为零用它。
这一层要讲透三件事，缺一不合格：

1. **背后**：浮点没有「相等」，所以判据必须写成不等式；eps 是机器能分辨的极限，容差是人对它的放大。
2. **设计**：为什么系数取 `8n`（运算步数的量级）、阈值怎么反推（`e_tol / e_worst` 落在哪个量级）。
3. **数值**：这个阈值在什么条件下失效（病态、相消、尺度悬殊），失败时长什么样。

因此数值库的章首单元承载「设计取舍 + 状态统计 + 落点文件」，正文单元承载数学与判据；
**不允许**把 `graphics/docs` 的规范句子复制一份过来当正文。

### 3.4 状态词照抄 survey 的五值

`已实现` / `框架` / `骨架` / `未建` / `缺位`。**这五个词就是失效点**：公式可信不等于数值已验证。
章首必须给出本章的状态分布，读者一眼能看出哪些是「已实现可跑」、哪些只是「契约写好了」。

## 4. 路线页：为什么只合并入口

### 4.1 现状

顶栏已有「🧭 切入点」（`#angles`），是一篇**单页长文**：从经典微积分到算子代数的一条具体路线。
`bridges/` 则是另一套东西：按结构动作分篇的跨领域串讲。两者都被读者当成「从哪进」，
于是有两个入口，互相不知道对方存在。

### 4.2 做法

**合并入口，不合并正文**：

- 一个「路线」入口，页面分两段：**数学切入线**（现有切入页，单页不拆单元）+
  **工程切入线**（`bridges` 五篇，按 S1–S6 排序）。
- `bridges` 正文**只存在一处**：数值库域的工程切入线章。路线页只引用标题与首句，
  点进去落到单元。
- 单页长文不拆单元的理由：它是一条**连续论证**，拆成卡片会切断上下文；而 `bridges` 本来就是
  结构化的（一篇一个动作），拆成单元反而更好读。

### 4.3 判据

- 路线页上**不允许出现第二份正文**：要么摘一句，要么给链接。
- 新增一篇「切入」类内容时，先问它属于哪一条 track；都不属于就说明应该进主站，不进路线页。

## 5. 维护

### 5.1 改动入口

| 要改什么 | 改哪里 | 然后 |
|---|---|---|
| 加/删章 | `content-map.json` 的 `lines[].chapters` + `json/<章>/` | 跑 `npm run check:content-map` |
| 加一条线 | 同上，并确认它只属于一个域 | 同上 |
| 改数值库映射 | `numericChapters[]`（`surveyEntries` / `libraryFiles`） | 同上 |
| 改路线页 | `routePage.tracks` | 同上 |
| 记录已知错位 | `fixups[]`（谁在什么时候修） | 不用改数据，导入期处理 |
| 源笔记改了内容 | **不改 json**，重跑搬运 | `npm run import:docs` → `npm run verify:docs` |

### 5.2 校验判据（`node tools/check-content-map.mjs`）

1. **章覆盖**：每条线的章并集必须覆盖 `json/` 下全部章目录 + 全部数值库章，且每个章只出现一次；
   线上出现既不是目录、也不是数值库章的代号 = CRIT。
2. **组归属**：每条线的 `group` 必须存在于 `groups[]`；每个组至少一条线。
3. **编号全集**：数值库各章的 `surveyEntries` 展开后必须与编号空间完全不重不漏。
4. **代号格式**：章 `^[A-Z]{2}\d{2}$`，与 `loader.ts` 的 `CODE_RE` 同源；数值库章连续。
5. **落点非空**：每个数值库章必须有库文件、桥接源文件，或显式 `status: unbuilt`。
6. **站点唯一**：`dataRoot` 与 `entryHtml` 不得重复。

另有一条独立的公式闸门 `node tools/check-katex.mjs --subject <站>`：
把每个单元的 `$…$` / `$$…$$` 真的交给 KaTeX 跑一遍（代码块内的 `$` 不算）。
无损对账只保证「文字没丢」，不保证公式还能编译 —— 这两件事必须分开验。

判据只读**目录名与内容表**，不解析任何 Markdown —— 中文表格不是机器格式。

### 5.3 与渲染的分工

`lines` 是**数据**。侧栏什么时候真正按「组 → 线 → 章 → 单元」渲染，是下一期的事；
本期 `taxonomy.ts` 只把线表接进来并提供查表函数，`sidebar.ts` 不动。
先定结构再改渲染，避免「结构还在改、断言已经写死」。

## 6. 导读侧车（`guide/`，guide-card/v1）

**它不属于内容总图，也不进单元 json**：导读层是单元页顶部的一段教学导语，
与 doc-card 的正文分成两份数据，避免 importer 的「拼回无损」判据被污染。

| 事实 | 位置 |
|---|---|
| 规范 | `build/guide/prompt/guide-card.md` |
| 映射（talk/单元 → 代号） | `guide/<site>/_map.json`（`build/guide/make_map.py` 生成） |
| 施工状态 | `guide/<site>/_progress.json`（done / skip / pending + talkSha/unitSha/noteSha） |
| 正文 | `guide/<site>/<章>/<代号>.json` |
| 站点级导语 | `guide/<site>/__site.json`（`scope: "site"`，只在总纲页挂） |
| 闸门 | `node tools/check-guide.mjs --site <id>`（`npm run check:guide`） |

**映射键**：`_map.json` 的 `units[code]`，`code` 与单元 json 的 `code` 同源；
talk 按 `408-kp-<学科>-<四位>` 或 `408-kp-<四位>`（数据结构老命名）对齐 `meta.kp`。

**覆盖判据**：每个 code 必须 `done` 或显式 `skip`；`--allow-incomplete` 只放宽 pending，
不放宽任何结构判据。跳过必须写 `reason`。

**Mode**：408 / 英一+数一是 `T`（有逐单元 talk）；工程线、数学系+工程数学是 `S`
（无 talk，从 unit json + notebook 源合成）。两侧共用同一套 schema 与闸门。

**source 三层**：`unit` 永远指向知识单元 json；`note` 是 Mode S 的 notebook 内容源
（`.tex` / `OUTLINE.md`）；`talk` 是 Mode T 的口述稿。`__site` 没有单元 json，
`unit` 沿用 `notebook/projects/README.md`。三层各自记 sha，漂移按单元判。
